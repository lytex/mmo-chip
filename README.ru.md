# mmo-chip — analog-re-wip

> [**ENG**](README.md) | **RU**

**Форк [mmo-chip](https://github.com/giulioz/mmo-chip) для реверс-инжиниринга аналоговых и mixed-signal ИС.**  
Расширяет оригинальный цифровой CMOS-маршрут до **BJT, BiCMOS, резисторов, конденсаторов, диодов** — экстракция на уровне отдельных транзисторов с экспортом нетлиста SPICE/CDL/Spectre.

## Об этом форке

[flxkrlv/mmo-chip-a](https://github.com/flxkrlv/mmo-chip-a) расширяет оригинальный [mmo-chip](https://github.com/giulioz/mmo-chip) сценариями реверс-инжиниринга аналоговых и mixed-signal микросхем. В проект также вошли существенные улучшения обработки изображений и пользовательского интерфейса от [lytex](https://github.com/lytex). Описание возможностей приведено в соответствующих разделах ниже.

## Благодарности

Many thanks to the developers of the original [mmo-chip](https://github.com/giulioz/mmo-chip) for the clean architecture and clear interfaces that made this analog extension possible.

Отдельная благодарность [lytex](https://github.com/lytex) за большой вклад и многочисленные улучшения, которые помогли развить проект.

## Десктоп-приложение (бинарная сборка)

Приложение целиком упаковывается в Electron-бинарь: бэкенд, фронт, MCP,
забандленный ngspice и vyges-lvs — ничего ставить не нужно:

```sh
npm run desktop:build:win    # → desktop/build/dist/ (zip + win-unpacked)
npm run desktop:build:linux  # → AppImage + deb
```

### Режимы запуска

| Команда | Что делает |
|---------|------------|
| `mmo-chip.exe` | **Локальный (по умолчанию)** — поднимает свой бэкенд и открывает окно на `http://127.0.0.1:3101` |
| `mmo-chip.exe --serve` | **Общий сервер** — поднимает бэкенд без окна; в трее список LAN-адресов. Закрытие окна сервер не гасит (то же через env `MMOCHECK_ROLE=server`) |
| `mmo-chip.exe --connect <host:port>` | **Клиент** — без своего бэкенда; окно подключается к удалённому серверу |
| `mmo-chip.exe --local` | Забыть сохранённое удалённое подключение, вернуться к локальному режиму |
| `mmo-chip.exe --dev-vite` | Dev — подключиться к работающему стеку `npm run dev` (Vite на :5173), ничего не спавня |

### Командная работа: один сервер, много клиентов

1. Один человек запускает общий сервер: `mmo-chip.exe --serve`. При первом
   запуске разрешите Windows Firewall (или откройте TCP 3101 вручную) —
   в трее появятся адреса для коллег.
2. Все остальные открывают `http://<ip>:3101` в обычном браузере — ничего
   ставить не нужно. Вместо вкладки можно окно десктоп-клиента:
   `mmo-chip.exe --connect <ip>:3101`. Адрес запоминается, последующие
   запуски подключаются сами; `--local` возвращает локальный режим.
3. Все данные и тяжёлые задачи (ngspice, LVS, ML) живут на машине сервера —
   клиентам нужен только браузер.

Auth опционален: задайте `JWT_SECRET` на сервере — потребуется вход
(в приложении есть страница login/register); без него полный доступ есть
у всей LAN.

ML опционален: запустите `setup_ml.bat` / `setup_ml.ps1` (Linux: `setup_ml.sh`)
в папке приложения — Python-sidecar установится как плагин (GPU
определяется автоматически); приложение подхватит его при следующем запуске.
Без него всё остальное работает сразу.

Без системной рамки — тайтл-зона с кнопками окна рисуется самим приложением;
MCP доступен на `http://127.0.0.1:3101/mcp` (+ `.mcpb` для Claude Desktop).
Подробности: [docs/DESKTOP_BUILD.md](docs/DESKTOP_BUILD.md).

## Данные и редактирование

Можно открывать проекты в старых форматах `data/`. Изображения кристаллов и overlay поддерживают пирамидальные/тайловые TIFF, включая SubIFD/OME-TIFF и SVS. Фоновая генерация тайлов продолжается после перезапуска бэкенда и пропускает уже созданные тайлы. Удаление overlay с сервера удаляет изображение для всех пользователей проекта.

Инструменты провода и полигонов поддерживают свободный, ортогональный, горизонтальный, вертикальный и диагональный режимы угла, сохраняемые отдельно для каждого кристалла. Удерживайте `Shift`, чтобы размещать точки свободно. Цвета via, ячеек и нетов можно посмотреть или скопировать из Inspector; цвета via сохраняются в проекте. Подсказки показывают горячие клавиши, всплывающие окна поддерживают прокрутку.

Линейка, провода, шина, полигоны floorplan и via запоминают режим угла для каждого кристалла; видимость отдельных областей, нетов, ячеек и комментариев можно переключать независимо от глобальных настроек.

## Поддерживаемые устройства

| Устройство | Детекция | Параметры |
|-----------|----------|-----------|
| **NMOS / PMOS** | Well-based через Clipper2 (разрезание diffusion по poly gate). Маркеры не нужны | W, L, fingers, M. Bulk: контакт на well → netId; нет → VDD/GND |
| **NPN** | Маркер `npn_id` + collector/base/emitter | AE (overlap base∩emitter), M |
| **PNP / LPnp** | Маркер `pnp_id` | AE, PE (периметр эмиттера), M |
| **Диод** | Маркер `diode_id` **или** NPN/PNP без коллектора | Площадь (AE из base-emitter overlap) |
| **Резистор** | Геометрически: тело (poly/base/emitter/hsr/film) → ME1 → контакты → PLUS/MINUS. Маркер не нужен | Ω или squares × Rₛ. Слои: poly-R, p-base, n+, HSR, thin film |
| **Конденсатор** | Маркер `cap_id` (overlap-область) | fF = площадь × плотность (не тестировалось) |

## Как рисовать устройства

Все слои рисуются в **Cell RE** соответствующим инструментом (rect/polygon/polyline).

### MOS

| Слой | Назначение |
|------|------------|
| `nwell` / `pwell` | Карман — nwell→PMOS, pwell→NMOS |
| `diffusion` | Область истока + стока |
| `polysilicon` | Затвор(ы), пересекающие diffusion |

1. Нарисуйте карман → diffusion внутри → polysilicon поперёк diffusion  
2. **Bulk:** `cont` на кармане **вне** diffusion/poly. Нет контакта → VDD (PMOS) / GND (NMOS)  
3. **Multi-finger:** Clipper2 разрезает diffusion между затворами → N отдельных MOS  
4. **Metal-connected D/S:** сток/исток, соединённые ME1 (или ME2+via) внутри ячейки, получают общий netId  

> Подробнее: [`docs/mos_detection.md`](docs/mos_detection.md)

### BJT

| Слой | Назначение |
|------|------------|
| `npn_id` / `pnp_id` | Bounding box |
| `collector` / `base` / `emitter` | Области прибора |

1. Нарисуйте bounding box → слои внутри → `cont` на каждом слое (терминалы сопоставляются автоматически)  
2. **Multi-emitter:** несколько эмиттеров → суммирование AE, M = количество  
3. **PNP/LPnp:** PE = периметр эмиттера (основной параметр)

### Диод

**Рекомендуется:** NPN/PNP без коллектора → автоматический диод. Base = анод, emitter = катод.

### Резистор

| Слой | Назначение |
|------|------------|
| `poly` / `base` / `emitter` / `hsr` / `film` | Тело (выберите один) |
| `contact` | Контакты (мин. 2) |

1. Выберите **body-слой** → рисуйте **polyline-инструментом** (`L`) — ортогональный snap, ширина в тулбаре (0–200 µm)  
2. Нарисуйте ME1, перекрывающий тело → поставьте 2+ контакта (станут PLUS/MINUS)  
3. Клик на любом сегменте → выделяется вся цепочка → ширина в правой панели  
4. Opacity-слайдер помогает выровнять ширину по изображению  

> **Sheet R₀:** настраивается в GUI (poly=25, hsr=1500, pb=200, npl=5, film=500 Ω/□)

### Конденсатор

Нарисуйте `cap_id` (bbox) — PLUS/MINUS оба на `contact`. Не тестировалось.

## Metal Stack (настраиваемая многослойная металлизация)

Die viewer поддерживает 1–6 слоёв металла (ME1–ME6) с соответствующими via (VIA12–VIA56).

### Настройка

**Net Settings** (шестерёнка рядом с "Nets") → **Metal layers** (1–6). Сохраняется per-project, перезагрузка не нужна. По умолчанию: 6 металлов.

| Элемент UI | Адаптация |
|------------|-----------|
| Палетры цветов слоёв | Только настроенные металлы |
| Чипы Wire/Via в тулбаре | Только настроенные металлы/via |
| Hotkeys 1..6 / Alt+1..5 | В пределах стека |
| E/Q via up/down | Берёт правильный via из стека |
| W cycle | Только по настроенным металлам |
| ProblemNavigator | Проверяет dangling via по правильной паре |

### Цвета слоёв

Настраиваются в Net Settings / Via Settings. Сохраняются per-project.

### Via labels

При zoom ≥ 8× каждая via показывает тип (VIA12, VIA56…) по центру — чёрная подложка, белый жирный текст. Включение: **VIA LABEL** в правой панели.

## Возможности Die Viewer

### Большие изображения и overlay-слои

- Импорт кристаллов и overlay-слоёв из пирамидальных или тайловых TIFF, включая SubIFD/OME-TIFF и SVS. Для дальнего масштаба используются сохранённые уровни пирамиды; тайлы высокого разрешения декодируют только свою область.
- Фоновая генерация тайлов возобновляется после перезапуска бэкенда и пропускает уже созданные файлы.
- Overlay-слой можно удалить с сервера; удаление влияет на всех пользователей проекта.
- Экспортируйте скриншоты в очень высоком разрешении через панель разрешения (см. [Скриншот](#скриншот)).

### Wire Tool

- **Переключение слоёв:** `W` активирует; повторно — цикл по стеку (ME1→…→ME6→ME1)  
- **Via (E/Q):** ставит via на конце превью (по умолчанию). Переключалка **Via: cursor / wire-end** в тулбаре  
- **Cross-layer snap:** провода разных металлов соединяются только через via-аннотацию  
- **AutoVia (checkbox):** при клике на вершине соседнего металла via ставится автоматически  
- **Via tool (O):** включает режим via; повторно — цикл по типам (VIA12→VIA23→…)  
- Контакты устройств подключаются только к **ME1** — ME2+ требует via
- **Multi-wire (`B`)** поддерживает несколько изгибов и выравнивает разнесённые начала проводов по общему фронту.
- Ширина провода сохраняется отдельно для каждого кристалла. Для отдельных нетов можно задавать цвет и видимость; видимость отдельных ячеек переключается независимо от глобальной.
- Удерживайте указатель над нетом в Outline Tree или на canvas, чтобы приблизить его. Крестики на вершинах нетов можно показывать или скрывать.
- Ячейки можно поворачивать и отражать через контекстное меню. Маркеры изменения размера позволяют менять размер ячеек одного типа.
- I/O-точки можно перетаскивать, а их подписи — отдельно показывать или скрывать. Несколько пэдов могут иметь один номер пина: пэды можно копировать и вставлять, а переименование одного обновляет все пэды этого пина.
- Двойной клик по нету открывает окно его переименования и выбора цвета. Двойной клик по ячейке позволяет сменить её тип. Окна можно перетаскивать; при панорамировании и зуме они остаются привязаны к объектам.
- Двойной клик по I/O-пину на canvas позволяет переименовать его. Прямоугольник выделения остаётся привязан к кристаллу при зуме и прокрутке и автоматически прокручивает вид у края canvas.
- Нижняя панель показывает сведения об объекте под указателем.

### ProblemNavigator

Панель проблем (`IssuesChip`): connectivity (неподключённые терминалы), wiring (обрывки), vias (dangling по паре металлов), I/O pins, overlaps, electrical warnings.

> [`docs/problem-navigator.md`](docs/problem-navigator.md) (на англ.)

### Операции с ячейками

| Действие | Как |
|----------|-----|
| **Copy / Paste** | `Ctrl+C` / `Ctrl+V` или ПКМ |
| **Make Unique** | `Shift+U` или ПКМ — отвязать ячейку от типа, редактировать независимо |
| **Поворот / отражение** | ПКМ по ячейке → Rotate 90° clockwise / Flip horizontally / Flip vertically (всё выделение, если ячейка выделена) |
| **Копирование I/O-пэдов** | Выделить пэды + `Ctrl+C` или ПКМ → Copy pad; `Ctrl+V` добавляет пэды с тем же номером пина и именем |
| **Cell Relationship** | **CELL REL** в правой панели — подсветка всех ячеек того же типа |

### Device Registry

Каждое устройство получает стабильный UUID из `kind + позиция + subType`. Переименования и оверрайды параметров сохраняются при переизвлечении и между сессиями.

### Слои (Cell RE)

| Слой | Группа |
|------|--------|
| `diffusion` / `polysilicon` / `nwell` / `pwell` | MOS |
| `collector` / `base` / `emitter` | BJT |
| `hsr` / `film` | Резисторы |
| `npn_id` / `pnp_id` / `res_id` / `cap_id` | Маркеры |
| `metal1`–`metal6` | Металлизация |
| `via1`–`via5` | Via-слои |
| `contact` | Контакты |

### Скриншот

`Ctrl+Shift+S` (или кнопка скачивания в SubBar) — экспорт текущего вида в PNG, композит всех overlay-слоёв включая analog device highlights.

**ПКМ по кнопке** открывает панель разрешения: ползунок от 0.5× до **native**-разрешения кристалла при текущем зуме (один пиксель результата на пиксель самого детального уровня тайлов, не меньше 4×), итоговый размер в пикселях и режим **Native**, который следует за зумом. Выбор запоминается. Более высокие значения заново рендерят вид и подгружают более детальные тайлы, поэтому добавляют реальные детали; изображение рендерится полосами и потоково записывается в PNG, так что может быть намного больше экрана (до 2 гигапикселей). Пока грузятся тайлы, показывается прогресс; долгий экспорт можно отменить. Наложенные поверх рисунки (analog highlights, комментарии) растягиваются из экранного разрешения.

### Поиск

`Ctrl+F` — фильтрация Outline Tree по имени net/cell. Enter фокусирует первое совпадение на canvas. Esc закрывает. Иконка поиска в заголовке "Items".

### Прочее

- **Net ID overlay:** имена нетов на die viewer (вкл. в боковой панели). VDD/GND скрыты  
- **Комментарии на топологии:** иконки с текстом, автором, ответами (WebSocket)
- **Панель горячих клавиш:** `Ctrl+/` — модальное окно со всеми шорткатами. Кнопка `?` в TopBar

## CV-детекция ячеек

Инструменты компьютерного зрения для автоматического обнаружения экземпляров ячеек. Доступны в правой панели (вкладка CV).

| Метод | Статус | Описание |
|-------|--------|----------|
| **Template matching** | Стабильный | Sobel-шаблонное сопоставление с референсным кропом. Основной рабочий метод детекции. |
| **AKAZE verify** | Опционально | Попарное сравнение найденных ячеек через AKAZE-кейпоинты. Ячейки ниже порога схожести удаляются. Фильтрация ложных срабатываний после template matching. |
| **Contour detection** | Экспериментальный | Детекция на основе контурных деревьев. Пока не работает стабильно. |

## Schematic Viewer

Принципиальные схемы уровня транзисторов из SPICE-нетлиста с **интерактивным канвасом** (движок по умолчанию).

- **Интерактив (по умолчанию)** — перетаскивание устройств, фиксация позиций (сохраняется), мультивыбор, поворот/зеркалирование символов, undo/redo
- **Иерархия** — floorplan-регионы как свернутые блоки с подписями портов; двойной клик / ПКМ по блоку — открыть его схему. Вкладки регионов (All, bandgap, …)
- **I/O pins** — пины и нетсы уровня кристалла
- ELK-раскладка (strategy/direction/compaction + настройка зазоров/рёбер в Netlist Settings), zoom колесом с Ctrl, тултипы имён нетов на проводах
- Экспорт: PNG, SVG (чёрно-белая)
- **Legacy static рендер** (netlist2svg, опционально): тумблер Static/Interactive, функциональная блок-диаграмма, кнопки pan/zoom, скачивание SVG/PNG/JSON

## LVS (Layout vs Schematic)

Сравнение извлечённого нетлиста из mmo-chip-a с нарисованной вручную схемой в стороннем САПР.

| Режим | Когда |
|-------|-------|
| **name-based** | Только если имена устройств совпадают (Q1, M2, R5…) |
| **vyges-lvs** | Name-independent сравнение топологии (netgen-подобный). |

Доступно на вкладке Analog Netlist (`Alt+4`).

## Floorplan Regions

Прямоугольные/полигональные регионы для разметки аналоговых блоков. Доступны цвет, имя, алиасы портов, резервация, глобальное переименование нетов, port dots, редактирование геометрии после создания, копирование/вставка, многострочные имена и индивидуальная видимость. Изменения поддерживают undo/redo; выбранный регион показывается в Inspector. `Esc` выходит из инструмента, `Enter` или двойной клик завершает полигон, `Space+H` переключает видимость floorplan.

| Клавиша | Действие |
|---------|----------|
| `H` | Активировать инструмент |
| `Ctrl+Shift+H` | Показать/скрыть overlay |

## Комментарии на топологии

Комментарии и ответы синхронизируются через WebSocket. Перетаскивайте маркер, чтобы переместить комментарий; автор может редактировать и удалять свои комментарии и ответы, изменения можно отменить. ## Merge Cells

Сравнение и выравнивание экземпляров ячеек одного типа. Multi overlay показывает их все одновременно; повёрнутые экземпляры вырезаются по реальному контуру на кристалле и показываются прямо, в системе координат типа. Ручное и автоматическое выравнивание используют ту же систему, а после слияния сохраняется центр рамки ячейки. Линии растяжения (`S`) помогают по частям выравнивать геометрию с разным масштабом в режимах overlay, difference и candidate; изменения можно отменить. Миниатюры используют тайлы die viewer.

## SPICE-симуляция

Запускать ngspice для извлечённых аналоговых netlist можно непосредственно из приложения.

- Движок ngspice в WASM или на сервере
- Выбор полного netlist или отдельного subcircuit
- **Одна модель на тип устройства** — для NMOS/PMOS Level 1, EKV или BSIM4;
  для NPN/PNP Гуммель–Пун или Эберс–Молл; переходный, стабилитрон или
  Шоттки. Выбор одной модели не захватывает остальные типы, а собственная
  карточка пользователя всегда главнее библиотеки. Каждое имя `.MODEL`
  попадает в netlist ровно один раз — карточки больше не дублируются
- **Редактируемый вручную netlist симуляции** — что видно, то и считает ngspice
- **Представление testbench** — DUT всегда рисуется блоком с выводами, к
  которым подключены источники и нагрузки: плоский DUT (находка ИИ,
  рукописный фрагмент) оборачивается в `.subckt` с выведенными пинами, а
  subcircuit, который никто не инстанцировал, получает свой экземпляр
- **«Ask agent» как сворачиваемая правая панель** с трассировкой каждого
  прогона (netlist, измерения, предупреждения) в чате
- **Результаты, которым не нужна кривая** — запуск `.op` показывает значения
  `.measure` и рабочую точку таблицами, а не пустым графиком
- Поддержка `.param` и `.step` с отображением прогресса
- Представления waveform, schematic и сгенерированного netlist
- Интерактивный просмотр waveform и экспорт PNG на белом фоне
- Независимый LLM-чат для генерации и уточнения testbench-директив

Директивы testbench по умолчанию пусты и это намеренно: источники и анализ
зависят от пинов выбранного DUT, поэтому готовый пример всегда не подходит.
Попросите ассистента написать testbench — или напишите его сами.

Извлечённый netlist записан в синтаксисе Spectre, поэтому перед запуском он
проходит через `shared/spiceNetlist`: списки выводов в скобках становятся
позиционными, арифметические значения (`16.8*250`) — числами, `r=1.9*Rp` —
`{1.9*Rp}`, недостающие model cards добавляются типовыми, а первой строкой
вставляется комментарий-заголовок, иначе SPICE съедает `.model` как title.
Если в netlist нет директивы анализа, добавляется `.op` — иначе вместо
результатов схемы приходят встроенные константы ngspice.

Инструмент SPICE ассистента работает по тем же правилам и добавляет ещё
немного: он дополняет testbench, к которому не подключено питание, переименовывает
«землю» в node 0, инстанцирует забытый subcircuit, убирает повторённые
моделью строки устройств и возвращает результаты `.measure`. Если прогон
не удался — в ответе будет ошибка ngspice, а не тихий «успех».

`testdata/analog/lm2937_bandgap.cir` — готовый тестбенд опорного источника
(`ngspice -b lm2937_bandgap.cir` → `v(ref) ≈ 0.91 V` на типовых моделях).

| Клавиша | Действие |
|---------|----------|
| `Ctrl+Enter` | Запустить симуляцию |
| `Ctrl+,` | Открыть настройки симуляции |

## IC Package / Pin Planner

Сопоставление I/O-пинов кристалла с выводами корпуса по футпринту, сгенерированному через `@tscircuit/footprinter`.

Это инструмент для совмещения и разметки разварки, а не полноценное проектирование корпуса или механического посадочного места. Используются футпринты из библиотеки поддерживаемых корпусов; основной сценарий — сопоставить выводы корпуса с I/O-площадками кристалла.

- Выбор поддерживаемого футпринта с нумерованными выводами
- Переименование выводов корпуса непосредственно на canvas
- Поворот и зеркальное отражение кристалла относительно рамки корпуса
- Создание нескольких разварочных соединений между выводами корпуса и I/O-площадками кристалла
- Настройка ширины разварочного соединения, по умолчанию 30 µm
- Перенос имён из именованных соединений корпуса обратно в I/O-пины кристалла
- Экспорт вида совмещения в PNG и таблицы выводов в CSV

| Клавиша | Действие |
|---------|----------|
| `S` | Pan / zoom |
| `T` | Переименовать вывод корпуса |
| `W` | Создать разварочное соединение |

## LLM-анализ

Опциональный AI Assistant анализирует извлечённый netlist и создаёт ранжированные карточки предположений о возможной функции схемы, роли устройств или подозрительных подключениях. Карточки содержат уровень уверенности, reasoning, подтверждающие признаки, затронутые устройства и предлагаемые проверки. Перед созданием интерактивной карточки проверяются существование устройств и связность фрагмента через net; это не доказывает электрическую функцию.

Ассистент работает в режиме read-only. Предположения можно показать на кристалле, открыть в Net Graph и посмотреть как фрагмент netlist или schematic.

Во время обсуждения карточки модель может использовать управляемые tool calls, если они включены:

- **`mmochip_lvs_check`** — сравнить candidate subcircuit с reference LVS library `analog-circuits-sky130` по топологии. Активную библиотеку можно выбрать, а пользователь может добавить собственные reference cells из SPICE/Spectre subcircuit.
- **`mmochip_vision`** — запросить фрагменты кристалла и overlay layers для мультимодальных моделей, чтобы проверить геометрию устройств и подключение терминалов.
- **`mmochip_spice_sim`** — запустить серверную проверку гипотезы через ngspice и вернуть измерения симуляции. Инструмент приводит netlist к синтаксису ngspice, выполняет все запрошенные анализы и возвращает напряжения узлов вместе с результатами `.measure`; прогон без данных сообщается как ошибка, а не как пустой успех.
- **`mmochip_card_update`** — предложить структурированное обновление существующей карточки предположения.

Доступ к инструментам явно управляется пользователем. Модель предлагает предположения и признаки, а пользователь просматривает и проверяет результат.

### Ruler tool

Нажмите `K` и проведите линию по кристаллу. По умолчанию измерение строится ортогонально. Можно создать несколько рулеток: `S` выбирает рулетку, `Shift+click` выбирает несколько, а клик по пустому месту снимает выделение. `Delete` удаляет выбранные рулетки, `Shift+K` — все рулетки.

Масштаб задаётся через double-click или ПКМ → **Set scale from ruler**. После задания масштаба длина отображается в µm, а значения меньше 1 µm — в nm. При zoom меньше 20% неактивные рулетки скрываются, текущая и выбранная остаются видимыми.

## Что ещё не сделано

- **DMOS, диод Шоттки, VPNP, JFET** — нет детекции или маркеров  
- **Wire matching** — допуск = размер контакта × 0.5; возможны ложные срабатывания  
- **Редактирование polyline** после размещения (только перерисовать)  
- **Hierarchical netlist / floorplan** — интерактивный viewer поддерживает; alias collision и скорость rename требуют реального тестирования

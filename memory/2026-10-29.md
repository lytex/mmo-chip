## Вектор-режим (classical, no-model) — альтернатива ML для wire-детекции

Юзер предложил маршрут: векторизация металла по яркости/цвету (настраиваемо) →
скелет-граф → снап к контактам → wires. Без обучения. Решено делать в

### Ключевая архитектурная мысль
ML — это только «генератор маски». Вся даунстрим-цепочка (скелет → ветки →
снап → сшивка → traces→nets) уже написана и ML-агностична. Векторизация —
второй генератор той же маски. Переиспользовано: `extract_trace_skeleton`,
`buildNetsFromTraces`, снап-таргеты, слой-рендер паттерн, «Traces → nets».

## Фикс: «Empty or out-of-bounds bbox» при Show vector overlay

- Причина: фетч планировался в `draw()`, а он получает **per-tile** world
  rect (TileBounds.world = прямоугольник одного renderer-тайла). Тайлы
  канвы вне кристалла (паддинг сетки) давали вырожденный bbox после
  клампа → backend резонно отвечал 400. Заодно это было N мелких
  запросов вместо одного.
- Фикс: фетч перенесён в `beginFrame(frame)` — `RenderFrame.world` это
  ПОЛНЫЙ видимый мир кадра. Один viewport-запрос на изменение вида,
  кламп к кристаллу, гарды: вырожденный bbox → skip; площадь > 5 Mpx →
  подсказка «zoom in» (однократно, без шторма). `draw()` теперь только
  рисует из кэша регионов.
- При ошибке фетча invalidate больше не дёргается — персистентная ошибка
  (sidecar вниз) не ретраится сама каждые 300 мс; ретрай при следующем
  действии юзера.
- Урок: `draw(ctx, bounds)` у слоя получает bounds ОДНОГО тайла; для
  viewport-работы есть `beginFrame(frame)` с `frame.world`.

## Итерация по фидбеку юзера (пипетка/каналы/диагностика/свей)

Вопросы юзера и ответы:
- «Переключил канал — снова пипеткой?» НЕТ: семплы хранят RGB; при
  смене канала среднее пересчитывается из сохранённых rgb — жми Apply
  ещё раз (добавлено в хинт под селектом).
- «brightness — это что?» Это ЛЮМА (Rec.601: 0.299R+0.587G+0.114B, как
  cv2 RGB2GRAY) — одна яркостная плоскость, подходит для SEM и оптики;
  R/G/B — сырые цветовые плоскости (оптика). Подписи в селекте +
  поясняющий хинт.
- Маркеры пипетки: каждая проба рисуется янтарным крестиком на канве
  (рисуется даже при скрытом оверлее); семплы теперь {rgb, x, y}.

«Нет трасс» — диагностика (2 причины найдены):
1. Trace confidence слайдер (настройенный под ML!) режет и векторные
   трассы — score вектора это яркостный margin; outlines рисуются БЕЗ
   score-фильтра, трассы с фильтром → «периметр есть, центра нет».
   Теперь панель предупреждает о ненулевом фильтре, а ошибка
   материализации называет точные числа (собрано N / отброшено M).
2. width-фильтр: статистика dropped_width теперь в ответе /vectorize
   (фильтр перенесён из extract_trace_skeleton в vectorize_region) и в
   статусе панели («width-filtered: N»). Широкие шины в центре —
   классическая жертва widthMax.

«Инференс по всему кристаллу» (свей):
- backend/ml/vectorSweep.ts: блоки 2048 px, последовательный декод через
  runVectorize (3 ретрая на CV-gate 429), файлы dataRoot/vectorize/
  <dieId>/v1-<sha1(params+overlay)>/col_row.json. Job per die в памяти:
  start/stop/status. readBlocks(dieId,bbox,params) читает кэш, missing
  считает.
- Роуты: POST /vectorize/job/start {params, overlaySource}, GET /job,
  POST /job/stop, GET /vectorize/blocks?bbox&params.
- VectorizeLayer: блоки-кэш приоритетнее live (полное покрытие → рисуем
  из блоков; missing → blockMiss + live-дебаунс). clearCache чистит
  blockMiss — по завершении свея панель дергает clearCache.
- VectorSection: «Decode whole die» + прогресс + Stop; после complete —
  подпись «cached · N block(s)».
- Проверено на LM2937: свей 20/20 блоков (~2.5 мин), blocks bbox 4096² →
  4 блока, missing=0, 1570 трасс / 2426 контуров. Live-статистика:
  kept=311, droppedWidth=772.
- Баг по пути: снейк-кейс dropped_width vs droppedWidth в бэке —
  статистика терялась молча; поймал на live-проверке.

## Мин. зазор (разрывы) + мкм-калибровка слайдеров (идея юзера)

- Физика: в ИС есть техпроцессный минимум зазора между шинами; зазор
  меньше него — это НЕ два провода, а один, разорванный рельефом →
  мержить. Механизм уже был (морф-клоуз bridgePx: мостит зазоры ≤
  2·bridgePx px), но был безразмерным.
- Теперь при калиброванной ди (annotations.umPerPx > 0) слайдеры
  Min gap / Min length / Width min / Width max показываются В МКМ и
  конвертируются в px на запись (params и пресеты остаются px-based):
  Min gap µm → bridgePx = round(um2px(gap)/2); длина/ширина → round.
  0 = выкл (как просил юзер). Без umPerPx — слайдеры в px + хинт
  «поставь umPerPx линейкой».
- Подпись «Min gap (merges breaks)» + пояснение про техминимум.
  Синергия с width-фильтром: если слияние создало жирнее widthMax —
  ветка отсеется и будет видна в droppedWidth.
- Декодер/бэкенд не тронуты; тесты 9/9.

## Runs-декодер + бесшовный свей (0e499b3) — по фидбеку юзера

- Юзер: векторизация контуров почти идеальна, но трассы внутри — шум,
  разрывы, несколько трасс в одном контуре; тайловость даёт артефакты;
  нужны прямые прогоны, повороты только 90/45; один контур = один net.
- **ml/wire_runs.py («runs»)**: скелет → граф веток → (1) короткие шумовые
  руки выкидываются В ФАЗЕ ГРАФА (до растворения узлов! иначе пеньки
  держат узлы живыми) → (2) коллинеарные сквозные узлы растворяются
  (угол ≤30°), реальные Г/Т/X остаются → (3) DP epsilon 2.5 + слияние
  поворотов <20° → (4) компоненты выжившего графа = `group` у трасс.
  Синтетика: прямая+пеньки → 1 трасса 2 точки; Г → 1 трасса 1 поворот;
  Т → 3 ветви 1 группа; кольцо → 1 группа; диагональ → прямая.
- **Баги по пути**: (а) инверсия реориентации рёбер в мердже —
  конкатенация шла задом наперёд (ловится на «туда-обратно» полилинии);
  (б) MORPH_ELLIPSE vs RECT в бридже; (в) stats-ключ spurs→merged.
- **Свей v2 = бесшовный**: 20 паддированных кропов → /vectorize/mask →
  паста СЕРДЦЕВИН (офсет x0-cx0 БЕЗ двойного pad — двойной сдвиг дал
  нулевую маску, пойман по nonzero=0 в mask.png) → /vectorize/decode
  ОДИН раз на 57 Мп маске (~5.5 мин скелетизации). Buffers пишутся
  0/255, не 0/1 (порог >127!). full.json по хэшу параметров.
- **Гонки CV-гейта**: live-декоды браузера душат свей (429) → (1) свей
  эндпоинты выведены из-под гейта, (2) фронт гасит live-слой на время
  свея (vectorSweepRunning), (3) ретраи 20×3с, таймаут декода 30 мин.
  Ещё ловушка: убитый бэкенд оставляет «осиротевший» декод, держащий
  гейт ~5 мин (uvicorn логирует после завершения); лечится рестартом

## Octilinear decoder shipped (ml/polygon_axis.py + plumbing), 17/17 synthetic

- Ключевые уроки пивота: чистая полигональная меденная ось (Delaunay circumcenter, Yang-Brock-Moll) умерла на sliver-web фантомных junction'ах (кластеры circumcenter ~1px -> каскад spur-прунинга съедал прямую шину до середины). Гибрид: pixel-skeleton corridor graph (wire_runs._build_graph) как источник цепей + мой L2 octilinear-snap (float-anchor reach_off интервалами, momentum, exact-диагонали knight-move, straighten_legs <=4px, cleanup_kinks, fuse same-class, stitch через degree-2) - надёжно и 17/17.
- oct_class через round(ang/45) бесполезен для честности (любое направление ближе всего к какому-то 45) - честность через _leg_slant (|dy| / |dx| / ||dx|-|dy||/sqrt2) + short-legs >= 4 + viol + point-to-fit vs delta.
- cv2 scalar цвет в polylines/rectangle красит ТОЛЬКО channel 0 (OpenCV 4.13) - тесты сутул из-за этого.
- Delaunay/web-код остался в git-истории; pyvoronoi (Boost segment-Voronoi) как fallback если snap недотянет.
- δ=octDeltaPx (auto = max(0.75, widthMin/2)), per-point cap = min(delta, dist-0.5). octStrict зарезервирован, не подключён.
- UI: тогл Octilinear decodes (off by default), слайдер Delta snap. Кэш-хэш включает новые params.

## Отростки вместо искажения трассы (branch contact model)

- Юзер: подключение контакта ломает последний edge (он выходит из трассы
  и подтягивается к контакту). Причина: (1а) двигал конец трассы НА
  контакт, (1b/1c) вставляли КООРДИНАТЫ КОНТАКТА внутрь полилинии =>
  шип/излом.
- Новая модель: полилиния НИКОГДА не гнётся. Mid-wire контакт => разрез
  сегмента в ТОЧКЕ ПРОЕКЦИИ (коллинеарный, геометрия та же) + ветка-
  ребро от этой вершины к контакту. Контакт у конца => ветка от концевой
  вершины (конец не двигается). near-integer проекция => ветка от
  существующей вершины без разреза.
- Union: трассы с ветками к ОДНОМУ контакту объединяются по label (1.7) —
  координатный endpoint-key больше не видит это (концы не двигаются).
  В графе net: один узел на метку контакта (nodeAt по координатам),
  ребро branch-vertex -> contact-node.
- Min-contacts считает labels по branches. snappedEnds = числу веток
  (считается в splice единообразно). onContact в stitch всегда false =>
  midpoint-merge фрагментов (декод-швы), ок.

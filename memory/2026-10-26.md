# 2026-10-26

## Fix: overlay layer purpose save failed with "Not found"

Reported: changing **Layer purpose** in Overlay layers showed
`Failed to save layer purpose - not found`.

Root cause (reproduced on the live folder project `folder-7c7130a5fbba`,
`F:\MMOCHIP_WORKDIR\mmochip_tps2553_local`):

- `PATCH /api/dies/:dieId/overlay-images/:id` reached `writeManifest()`, which
  derived the manifest location from `manifest.originalPath` instead of the
  project/source directory.
- Folder projects that were copied/moved (here from
  `d:\SyncStore\Work\TPS\mmochip_tps2553_locall\...`) keep a stale absolute
  `originalPath` in `manifest.json`.
- Writing the manifest to that stale directory threw `ENOENT`, and the global
  Express error handler maps `ENOENT` to `404 {"error":"Not found"}` - exactly
  the toast message the user saw.

Fix (`backend/src/api/overlayImages.ts`):

- `writeManifest(dataRoot, dieId, manifest)` now resolves the target via
  `manifestPath(dataRoot, dieId, manifest.id)` (source dir is authoritative).
- While writing, if `originalPath` is stale and the original sits beside the
  manifest, the manifest is repaired to the local absolute path (tiles/CV
  readers then need no fallback).
- Both callers (upload, purpose PATCH) pass `config.dataRoot` and `dieId`.

Regression test (`backend/src/app.test.ts`): "overlay purpose saves when a
moved folder project has a stale originalPath" - uploads an overlay, rewrites
`originalPath` to `Z:\moved-away\...`, PATCHes the purpose, asserts 200, the
persisted purpose and the repaired `originalPath`.

Verification:

- `node --import tsx --test --test-name-pattern "overlay purpose" src/app.test.ts` -> 2/2 pass.
- `npx tsc -p tsconfig.json --noEmit` -> clean.
- Live check: PATCH on `folder-7c7130a5fbba` now returns 200 and repairs
  `originalPath` (`me1_sem` manifest). Full `app.test.ts` run has unrelated
  pre-existing Windows failures (EBUSY temp cleanup + assistant snapshot).

Note: during investigation a temporary PATCH set `purpose=metal1` on the
LM2937 `sirtl` overlay; reverted to `null` (auto -> diffusion) right away.

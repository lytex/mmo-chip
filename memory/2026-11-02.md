## 11:55 — Фикс: blockage «съедал» соседние trace вне его (репорт работника)

Причина найдена: я проверял blockage срезом на ПЕРЕСЕЧЕНИЕ bbox линии с прямоугольником (`rectsIntersectBox` в `classify` и `inNoBlockage(box, …)` в VectorizeLayer). L-образные/нерегулярные цепочки, у которых bbox лишь НАКРЫВАЕТ blockage (путь огибает его), и соседние trace рядом оказывались вырезанными.

Фикс — точечная геометрия вместо габаритного ящика:
1. `userNetFilter.ts`: новый экспорт `polylineEntersRect(points, rect)` — vertex строго внутри, ИЛИ сегмент пересекает внутренность (`segEntersRect`, через существующий `segsIntersect` по 4 рёбрам прямоугольника; T-касание края не считается). AABB-prejection для дешевого отсева. `classify` в `filterTracesByRegions` теперь режет в blockage ТОЛЬКО по этой проверке; region-тест остался габаритным (консервативное keep — это правильная сторона ошибки там).
2. `VectorizeLayer.ts`: `inNoBlockage` теперь принимает САМИ точки trace/outline (`region.traces[index].points`, `pin.…`), не box; вызовы переставлены так, чтобы pts извлекались до проверки. Импорт `polylineEntersRect` из userNetFilter.
3. Регрессионные тесты в `userNetFilter.test.ts` (blockage-геометрия, blockage-поверх-region, `polylineEntersRect`): +3, всего 500/500 зелёные, vite build чистый.

Нюанс геометрии (для будущих): для ПРЯМОЙ 2-точечной trace пересечение bbox с rect ⇔ пересечение геометрии (rect выпуклый: bbox накрывает обе оси ⇒ конец в противоложных углах ⇒ пересечение). Мимо rect с накрытым bbox могут пройти только ломаные цепочки — они и ломались UX.
